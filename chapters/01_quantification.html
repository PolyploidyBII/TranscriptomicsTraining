1  Quantification of transcript abundances

In this chapter, you will learn how to generate transcript abundance files from FASTQ files using the nf-core/rnaseq Nextflow pipeline. At the end of this chapter, you will be able to: - Understand the overall workflow of nf-core/rnaseq - Adjust pipeline parameters for different types of RNA-seq datasets, including single- or paired-end sequencing data, and datasets with or without spike-in standards.

1.1 Introduction to the nf-core/rnaseq pipeline

The nf-core/rnaseq pipeline is a standardized bioinformatics pipeline built using Nextflow, a workflow management system designed to enable reproducible and scalable computational analyses. The nf-core/rnaseq pipeline provides an integrated workflow for processing RNA-seq data. The pipeline performs quality control (QC), trimming and alignment, and produces a gene expression matrix (i.e., transcript abundance files) and extensive QC report. nf-core is a global community collaborating to build open-source Nextflow components and pipelines (Ewels et al. 2020).

1.2 Obtaining the example data set

Our example data set contains sequencing reads (FASTQ files) from 2 Arabidopsis thaliana genotypes, and three ploidy levels (2x, 4x, and 8x; see Preface for details). For the sake of demonstration, each example file contains only the first 5,000 reads from the corresponding original FASTQ file. Let’s download the example data from Zenodo and store them in a directory named rnaseq_data in the temporary directory (/tmp/). The FASTQ_example folder contains 25 example FASTQ files.

# Download the `FASTQ_example` folder to `/tmp/rnaseq_data/`
mkdir -p /tmp/rnaseq_data

## `FASTQ_example/`
wget -O /tmp/rnaseq_data/FASTQ_example.zip \
  "https://zenodo.org/records/22938731/files/FASTQ_example.zip?download=1"
unzip /tmp/rnaseq_data/FASTQ_example.zip -d /tmp/rnaseq_data && rm /tmp/rnaseq_data/FASTQ_example.zip

## `nextflow_metadata.csv`
wget -O /tmp/rnaseq_data/nextflow_metadata.csv \
  "https://zenodo.org/records/22938731/files/nextflow_metadata.csv?download=1"
sed -i 's|/blue/soltis/shan158538/PI3_node-1/tutorial/fastq_files_download/|/tmp/rnaseq_data/FASTQ_example/|g' /tmp/rnaseq_data/nextflow_metadata.csv

## Reference genome (FASTA)
wget -O /tmp/rnaseq_data/Athaliana_TAIR10.fa.gz \
  "https://ftp.ensemblgenomes.ebi.ac.uk/pub/plants/release-63/fasta/arabidopsis_thaliana/dna/Arabidopsis_thaliana.TAIR10.dna.toplevel.fa.gz"

## Reference annotation (GTF)
wget -O /tmp/rnaseq_data/Athaliana_TAIR10.gtf.gz \
  "https://ftp.ensemblgenomes.ebi.ac.uk/pub/plants/release-63/gtf/arabidopsis_thaliana/Arabidopsis_thaliana.TAIR10.63.gtf.gz"
  
## Sequences of spike-in standards (FASTA)
wget -O /tmp/rnaseq_data/ERCC92.zip \
  "https://assets.thermofisher.com/TFS-Assets/LSG/manuals/ERCC92.zip" && \
  unzip -j /tmp/rnaseq_data/ERCC92.zip ERCC92.fa -d /tmp/rnaseq_data && \
  rm /tmp/rnaseq_data/ERCC92.zip

For the input samplesheet file (i.e., nextflow_metadata.csv), the first four columns must be sample, fastq1, fastq2, and strandedness (in this exact order). The pipeline will auto-detect whether a sample is single- or paired-end using the information provided in the samplesheet. The strandedness column can be set to ‘auto’, allowing the pipeline to infer the library strandedness. Additional columns can be included in the samplesheet as needed, but the first four columns must follow the format and order described above.

1.3 Executing the pipeline

In our workflow, we run the pipeline to execute the following steps: basic QC with FastQC (Bioinformatics 2011), read trimming with fastp (Chen et al. 2018), read mapping to the reference genome with STAR (Dobin et al. 2013), and transcript abundance quantification with salmon (Patro et al. 2017). For each of these steps, you can either go with default parameters, or specify custom options in a params.yml file. Our params.yml looks like this:

aligner: star_salmon
seq_platform: ILLUMINA
trimmer: fastp
with_umi: true
skip_umi_extract: true
umitools_umi_separator: "_"
extra_salmon_quant_args: "--noLengthCorrection"

Of note, we’re using --noLengthCorrection in salmon because our data were generated with 3’ tagged RNA-seq data, so no differences in transcript length should be taken into account. To execute the pipeline on a SLURM cluster, you’d run the following script:

#!/bin/bash
#SBATCH --job-name=nextflow-rnaseq_v1
#SBATCH --output=%x_%j.out
#SBATCH --error=%x_%j.err
#SBATCH --mail-type=ALL
#SBATCH --mail-user=your_email_address
#SBATCH --time=1-00:00:00
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=12
#SBATCH --mem=120GB
#SBATCH --qos=your_group

module purge
module load nf-core nextflow singularity

CSV=/tmp/rnaseq_data/nextflow_metadata.csv
GENOME=/tmp/rnaseq_data/Athaliana_TAIR10.fa.gz
GTF=/tmp/rnaseq_data/Athaliana_TAIR10.gtf.gz
SPIKEIN=/tmp/rnaseq_data/ERCC92.fa
PARAMS=params.yml

nextflow run nf-core/rnaseq \
  -r 3.26.0 \
  -profile singularity \
  -params-file ${PARAMS} \
  --input ${CSV} \
  --outdir . \
  --gtf ${GTF} \
  --fasta ${GENOME} \
  --additional_fasta ${SPIKEIN}

If you’re using your lab’s own server instead of a SLURM cluster, remove the lines containing ‘#SBATCH’ and module load calls. After executing the pipeline, you should be able to see star_salmon folder in its output directory. This is where you will find all transcript abundance estimations we will use in other chapters. Importing such quantifications to a final matrix of gene-level transcript abundances is the topic of the next chapter.
